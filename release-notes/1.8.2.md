kRO game files patched since November 5 open again, and two missing effects show again.

## Fixes

- **kRO data.grf "Incompatible GRF":** kRO's `data.grf`, as patched since 2026-11-05, was refused with `Invalid archive key block: Unsupported or truncated GRF archive key block`, so a setup using only kRO files couldn't start. The archive's key block now comes in a new format. The asset server reads it, rebuilds the default keys kRO leaves out, and checks the block's checksum before trusting any key. If a future change still doesn't verify, it opens the archive with the default keys and logs a warning, so only files that name a new key fail, one at a time. A damaged key block in any other format is still refused. Thanks @MondoTruth. (#770, Flux159/roBrowserLegacy-RemoteClient-Rust#19)
- **Two missing effects:** the Glass Wall effect asked for its art in a folder no client has, so it never showed, and one item effect (EF_ITEM316) used a file kRO no longer carries. Glass Wall now finds its art, and the item effect falls back to one kRO has, leaving clients that still carry the original untouched. Thanks @MondoTruth. (#771, Flux159/roBrowserLegacy#236)

## Known issues

- **New kRO keys:** if Gravity changes the default keys themselves, protected files that use them will fail to load until the new keys are known. The asset server's log says so at start-up.
